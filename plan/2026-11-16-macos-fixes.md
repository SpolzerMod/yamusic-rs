# Фиксы после ревью macOS-порта (2026-11-16)

Статус: в работе. Ветка `macos` (база — `04c7574` v1.0.2 + порт).
Источник — ревью `origin/main..HEAD`; три подтверждённых бага, один из них с
воспроизводимым регрессионным тестом.

## Milestone 1 — `HttpStream`: перемотка вперёд при активном префетче

**Корневая причина.** `src/stream.rs::read` при `pos >= chunk_end` всегда берёт
заранее скачанный кусок `take_ahead(end)` и ставит `chunk_start = end`. При
перемотке вперёд (`seek` только меняет `pos`, кусок не сбрасывается) `pos` может
оказаться за пределами этого куска: `off = pos - chunk_start >= chunk.len()` →
`return Ok(0)`. Для `Read` ноль — это EOF, symphonia/rodio завершают трек.
Сценарий: скраббинг прогресс-бара в момент, когда до конца куска осталось ~64 КБ
(префетч уже запущен), с перемоткой дальше следующего куска.

**Проверка (RED).** Юнит-тест в `src/stream.rs`: локальный `TcpListener` с
поддержкой `Range`/206 и детерминированными байтами; последовательное чтение до
срабатывания префетча; `seek` за пределы префетч-куска; `read` должен вернуть
данные по новой позиции (сейчас вернёт `Ok(0)`).

**Фикс (GREEN).** Использовать `ahead` только для непрерывного перехода границы
(`pos == end`); при `pos > end` сбрасывать `ahead` и качать `fetch_chunk(pos)`.
После `take_ahead` дополнительно проверить, что `pos` попадает в кусок.

**Критерий:** новый тест зелёный; последовательное чтение и seek назад не сломаны.

## Milestone 2 — `win::pick_folder`: диалог молча не открывается

**Корневая причина.** `src/win/unix.rs::pick_folder` всегда подставляет
`default location (POSIX file "<start>")`. AppleScript коэрсит его в `alias`, а для
несуществующего пути падает (`-1700 Can't make file … into type alias`, проверено).
`start` по умолчанию — `~/Music/Яндекс Музыка`, создаётся только при первом
скачивании. Итог: на свежей установке пункт «Папка для скачивания» ничего не делает
(обработчик при `None` молча выходит).

**Проверка (RED→GREEN).** Вынести построение AppleScript в
`fn choose_folder_script(title, start)`; тест: для несуществующего пути строки
`default location` нет, для существующего (temp dir) — есть. Сначала тест на
текущем поведении (helper всегда подставляет) падает, затем добавляем `.exists()`.

**Критерий:** оба теста зелёные; на свежей установке диалог открывается.

## Milestone 3 — `player.rs::replay`: блокирующий HTTP при повторе

**Корневая причина.** Повтор (`Repeat::One`) вызывает `api.reopen_stream()` —
блокирующий запрос первого куска — прямо в потоке аудиодвижка при пустом sink.
Раньше повтор шёл из кэшированных байт мгновенно; после перехода на стриминг —
слышимый разрыв ~0.3–0.5 с.

**Фикс.** Открывать поток по уже известному `current_url` в фоновом потоке и
присылать `Msg::Audio` (как обычная загрузка). `current_url` не сбрасывать.
Тестом не покрывается (звук/потоки — по AGENTS только ручная проверка).

**Критерий:** повтор не блокирует движок; трек повторяется (ручная проверка).

## Surprises & Discoveries

- Подтверждено экспериментом: `POSIX file "<несуществующий>" as alias` → `-1700`,
  поэтому `default location` ломает весь `choose folder`, а не игнорируется.

## Decision Log

- Для M1 тест поднимает локальный HTTP-сервер на 127.0.0.1 (без внешней сети):
  так проверяется реальный путь `open`/`read`/`seek`, а не только чистая логика.
- Для M2 AppleScript вынесен в чистую функцию — единственный способ покрыть
  GUI-зависимый код без открытия диалога.
- Для M3 выбран `reopen_stream(current_url)` в фоне, а не `start_current()`:
  последний заново ищет ссылку (2 запроса) и обнуляет `current_url`.
- Тест-модули держим в конце файлов (clippy `items_after_test_module`).

## Outcomes & Retrospective

- M1 и M2 закрыты регрессионными тестами (red→green проверено вживую).
- M3 не покрыт юнит-тестом: звук и потоки по AGENTS проверяются вручную.
- Осталось: ручная проверка повтора (Repeat::One), перемотки в плеере и диалога
  «Папка для скачивания» на собранном бандле.
