# План аудита на «вредоносные» функции и лишнюю передачу данных

Цель: подтвердить, что приложение отправляет только данные, необходимые для воспроизведения
и работы с аккаунтом Яндекса, и не содержит функций, не относящихся к основному функционалу.
Базис — модель угроз в `SECURITY.md` (токен, обновлялка, парсинг ответов).

## Метод

1. **Инвентаризация исходящих соединений** — grep всех URL/хостов, каждый хост классифицировать
   и записать в таблицу «хост → данные → зачем → нужен ли».
2. **Инвентаризация полей запросов** — что реально уходит: заголовки, тело, query.
   Отдельно токен/cookies/refresh-токен.
3. **Ручной код-ревью** подозрительных паттернов (grep-список ниже) по всей `src/`.
4. **Автопроверка зависимостей**: `cargo audit` + `cargo deny` (в контейнере).
5. **Проверка логов**: прогнать сценарии, вычитать `log.txt` — токен и secrets не должны попасть.

## A. Сетевые хосты (ожидаемый полный список)

| Хост | Что отправляется | Зачем | Вердикт |
|---|---|---|---|
| `api.music.yandex.net` | токен, запросы API, фидбек прослушиваний | API Музыки | ✅ необходимо |
| `oauth.yandex.ru`, `ya.ru/device`, `id.yandex.ru`, `yandex.ru/user-id` | код устройства, токен-обмен | вход | ✅ необходимо |
| `storage.mds.yandex.net` | GET download-info, ID трека | ссылки на mp3 | ✅ необходимо |
| `avatars.mds.yandex.net`, `avatars.yandex.net` | GET адреса обложек | обложки | ✅ необходимо |
| `music.yandex.ru` | GET страниц лендинга, iframe-кода | разделы интерфейса | ✅ необходимо |
| `api.github.com` | GET `releases/latest` (UA с версией), GET `browser_download_url` (Windows) | проверка обновлений | ✅ необходимо; на Linux — только метаданные |
| `discord.com`/`discordapp.com` через IPC-пайп (Windows, `discord.rs`) | трек, исполнитель, обложка-URL, прогресс | Rich Presence | ⚠️ не влияет на воспроизведение — по умолчанию отключить на Linux, держать выключатель в настройках |

Контроль: токен уходит только на хосты `yandex.ru`/`yandex.net` по https — есть guard
`client.rs::token_allowed` с тестами на подмену домена (`evil.com`, `yandex.net.evil.com`,
`notyandex.ru`). Проверить, что **все** места отправки токена идут через него.

## B. Чек-лист код-ревью (grep-паттерны)

- [ ] Telemetry/analytics: `telemetry|analytics|collect|metrics|beacon|fingerprint`.
- [ ] Утечка токена: все `token`/`refresh_token` → только в `client.rs`-клиенты с guard; не в `log()`, не в Discord, не в MPRIS.
- [ ] Исполнение данных с сервера: `Command::new` с аргументами из ответов, `eval`-подобного нет; SVG → парсер Slint (surface: парсинг `yandex_id`).
- [ ] Скрытые каналы: необычные кодировки/base64-блобы, XOR/деобфускация, динамические URL.
- [ ] Запись файлов: только `config::dir()` (config, log, mpris-cover), `~/.config/autostart`, сокет `$XDG_RUNTIME_DIR`. Ничего в системных каталогах.
- [ ] Процессы: полный список spawn — `xdg-open`, `gsettings`, `wl-copy`/`xclip` (Linux), `clip` (Windows), `rc.exe` (build.rs). Никаких загрузчиков.
- [ ] IPC: MPRIS-методы маппятся только на команды плеера (PlayPause/Next/Prev/Seek/Volume/Repeat/Shuffle/Quit/Raise); wake-сокет принимает только `"wake"`.
- [ ] Обновлялка: только GitHub, только sha256-сверка (`update.rs::install`), на Linux — только открытие страницы; не подписывать и не запускать скачанное.
- [ ] DPAPI-функционал (Windows) не задействован для чего-либо кроме токенов.

## C. Автоматика

- [ ] `cargo audit` (контейнер) — known CVEs в дереве зависимостей.
- [ ] `cargo deny` (advisories/licenses) — в CI Linux-джобу.
- [ ] Тест `token_allowed` продолжает падать на подмену доменов (regression-тест).

## D. Критерии прохождения

1. Каждый исходящий хост — из таблицы A. Любой новый хост = правка кода.
2. Токен ни разу не появляется в логах и вне yandex-хостов.
3. Все функции, передающие данные третьим лицам (только Discord), отключаемы и по умолчанию выключены на Linux.
4. Нет записи файлов и процессов вне списков B.
5. `cargo audit` без open advisories или с задокументированными.

## Ход исполнения

Ревью — отдельным проходом после стабилизации ветки `linux-port`; результаты фиксируются здесь
же (галочки + найденные отклонения). Автоматика (cargo deny) добавляется в CI в той же ветке.
