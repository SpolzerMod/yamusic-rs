# Унисон / Ynison Connect

Нативная экспериментальная интеграция для управления этим плеером из официальной
Яндекс Музыки. Python, браузер и дополнительные службы не нужны.

Результаты сборки, тестов и замеров: [ynison-validation.md](ynison-validation.md).

## Включение

1. Войдите в Яндекс Музыку RS обычным способом.
2. Откройте **Настройки → Унисон / Ynison**, включите переключатель.
3. При необходимости измените имя и нажмите **Сохранить имя устройства** (или Enter).
   Смена имени перезапускает соединение, но не аудиодвижок.
4. Дождитесь статуса **Подключено**. Названия устройств из ответа сервера показаны
   под кнопкой сохранения; это информационный список, не переключатель устройств.
5. На телефоне войдите в **тот же аккаунт**, откройте официальный клиент Яндекс
   Музыки, начните воспроизведение и откройте выбор устройства в плеере.
6. Выберите имя компьютера. Подключение само по себе не захватывает воспроизведение.
   Локальное нажатие Play/Next или выбор очереди может сделать компьютер активным.

Для выключения достаточно переключателя; настройка сохраняется. По умолчанию
интеграция выключена. Токен вручную вводить или присылать разработчику не нужно.
«Требуется повторный вход» означает необходимость выйти и войти заново.
После вытеснения устройства выключите и включите Ynison.

## Что изменено

- `src/ynison/connect.rs`: постоянный WebSocket, redirector, видимый player,
  версии protobuf JSON со строковыми int64, heartbeat, ограничение размера сообщений,
  reconnect/backoff, остановка и сокрытие credential-bearing ошибок.
- Сеть работает на отдельном current-thread Tokio runtime, аудио — на прежнем
  rodio-потоке. При выключении нет ожидания сети в UI/audio thread.
- Последний исходящий снимок заменяет предыдущий через watch; входящий mailbox
  содержит не более трёх событий (status/devices/state), с одним уведомлением
  аудиопотоку. Загрузка метаданных очереди — один запрос плюс последний ожидающий
  снимок; устаревшие результаты отбрасываются по epoch/revision.
- Входящие play/pause, seek, volume, текущий индекс и очередь используют существующий
  Engine. Потеря владения ставит локальный плеер на паузу. Собственные версии и
  непосредственная обработка удалённых команд не запускают обратную командную петлю.
- `src/config.rs`, `src/gui.rs`, `ui/state.slint`, `ui/account.slint`: выключатель,
  имя, статус и список устройств в существующем стиле настроек.
- `src/ynison.rs`: чтение порядка shuffle, проверка индексов и типов контента.
- Добавлены `tokio-tungstenite`, прямые ссылки на уже используемые транзитивно
  Tokio/futures-util. Chromium/Electron и отдельный сервис не добавлялись.
- Android manifest обновлён для общего Rust-кода; Android-сборка не проверялась.

## Проверка с физическим телефоном — обязательна

Эти проверки требуют аккаунта с доступом к музыке и официального клиента; локальные
тесты не доказывают совместимость с production-сервисом:

| Проверка | Действия / ожидаемый результат |
|---|---|
| Обнаружение | После включения компьютер появляется в выборе устройства телефона |
| Перенос | Телефон → компьютер: тот же трек и близкая позиция, звук только на компьютере |
| Play/pause | С телефона и компьютера; состояние отражается на втором устройстве |
| Next/previous | Несколько переходов, включая возврат к предыдущему треку |
| Seek | Перемотка в обе стороны и несколько быстрых перемоток подряд |
| Volume | Изменение с телефона и компьютера; нет скачков и командного эха |
| Очередь | Смена альбома/плейлиста, выбор другого индекса, добавление треков |
| Repeat/shuffle | Очередь с перестановкой и repeat none/one/all |
| Владение | Переключение обратно на телефон останавливает звук компьютера |
| Reconnect | Отключить сеть на минуту, вернуть; проверить обнаружение и управление |
| Lifecycle | Выключить/включить интеграцию 20 раз; выйти из аккаунта; закрыть приложение |
| Отказ доступа | Отозвать токен: понятный статус, нет бесконечного быстрого reconnect |

Не публикуйте config.json, OAuth-токен, redirect ticket, session id или сырые
WebSocket-заголовки при отправке отчёта.

## Ограничения

- Ynison — неофициальный, меняющийся протокол; доступность Connect зависит от
  аккаунта, региона и версии официального приложения.
- Передача на компьютер реализована через active-device state. Кнопки отправки
  воспроизведения на другое устройство из RS пока нет: используйте официальный клиент.
- Поддержаны музыкальные TRACK; очередь с podcast/local/неподдержанными элементами
  не применяется, чтобы не сдвигать индекс и не включать неправильный трек.
- Недоступные API треки не подменяются; показывается ошибка загрузки очереди.
- Полученная shuffle-очередь линеаризуется в фактический порядок воспроизведения.
  Флаг shuffle UI при этом сбрасывается; исходная перестановка как отдельная сущность
  локальным движком не хранится.
- Переданная очередь радио воспроизводится как конечная очередь. Продолжение
  удалённой radio-session и полная семантика источника не реализованы.
- После reconnect регистрация не захватывает активность автоматически. Сервер должен
  прислать ownership; иначе повторно выберите компьютер или нажмите локальный Play.
- При выключенной интеграции сохраняется прежний одноразовый shadow resume/publish.
- При закрытии cancellation закрывает транспорт, но delivery последней позиции и
  graceful WebSocket close не гарантированы.
- Не подтверждены end-to-end, ресурсная цель +5–15 МБ, отсутствие регрессий старта,
  длительный soak и совместимость со всеми версиями клиента. Не считать production-ready.

## Сборка и тесты (Windows x64)

Нужны Rust MSVC, Visual Studio Build Tools C++ и Windows SDK:

```powershell
cargo test --locked
cargo build --release --locked
```

Результат: `target/release/yamusic-rs.exe`. Существующий ignored live-тест
`ynison::tests::live_round_trip` изменяет серверную позицию и не запускается
автоматически. Он проверяет только старый shadow-путь, не Connect с телефоном.

## Измерения

Скрипт `scripts/measure-process.ps1` снимает Working Set, Private Bytes и CPU
запущенного процесса без постоянного фонового агента. Сравнивайте одинаковые
release-сборки, аккаунт, окно/трей, трек, громкость и длительность. Не запускайте
два экземпляра одновременно: в приложении может быть single-instance guard.

```powershell
# Запустите baseline, затем получите PID из диспетчера задач:
.\scripts\measure-process.ps1 -ProcessId 1234 -Seconds 120 -Output baseline-idle.csv
# Повторите для новой сборки с выключенным и включённым Ynison:
.\scripts\measure-process.ps1 -ProcessId 5678 -Seconds 120 -Output connect-idle.csv
```

После 30 секунд прогрева измерьте минимум: signed-in idle (выключено/включено),
playback 5 минут, 100 команд с телефона, reconnect, 20 переключений настройки,
30 минут idle. CPU % скрипта нормирован на все логические процессоры
(как диспетчер задач), дополнительно выводится CPU time в секундах.
Logged-out idle не является замером накладных расходов активного Ynison.
